PHASE 3.1 — REAL-MATCH INTEGRITY PATCH

Phase 3 is complete and currently committed at the real-match coaching milestone.

The Phase 1–3 adaptive core is considered stable.

DO NOT rebuild the app.
DO NOT redesign the UI.
DO NOT add new features outside this patch.
DO NOT add authentication, database, cloud persistence, video analysis, opponent scouting, or premium visual redesign.

This phase exists only to fix THREE specific integrity issues found during post-Phase-3 code review:

1. Unsupported root-cause guessing for ordinary missed pots
2. Unsafe "Edit last frame" behaviour
3. Mixed Training ruleset allocation not using match-derived ruleset evidence

Preserve all existing tests and behaviour unless explicitly changed below.

1. PRESERVE THE PHASE 3 BASELINE
==================================================

Before changes:

1. Confirm current origin/main contains the Phase 3 milestone.
2. Confirm the working tree state.
3. Preserve unrelated local changes.
4. Do not weaken or delete existing tests.
5. Do not modify the Phase 2.1 rating/confidence/root-cause logic unless required by the three fixes below.

==================================================
2. FIX UNSUPPORTED MATCH ROOT-CAUSE GUESSING
==================================================

The current Phase 3 match inference incorrectly assumes that an ordinary:

missed_pot

was likely caused by:

Positional Execution

even when the player provided no evidence that poor position caused the miss.

This must be fixed.

A plain missed pot with no additional upstream evidence should remain:

reported/direct skill:
Potting

inferred root cause:
none / insufficient evidence

Do NOT invent an upstream cause simply because one is plausible.

==================================================
3. CONSERVATIVE MATCH CAUSE INFERENCE
==================================================

Update inferMatchCause() or equivalent so it follows this principle:

NO EVIDENCE → NO UPSTREAM DIAGNOSIS

Examples:

missed_pot only
→ direct skill: Potting
→ inferred cause: null

lost_position
→ direct skill: Positional Execution

poor_speed
→ direct skill: Speed / Touch Control

pattern_error
→ direct skill: Pattern Recognition

tactical_error
→ direct skill: Tactical / Safety Decision-Making

Only infer an upstream cause when structured contextual evidence supports one.

==================================================
4. OPTIONAL STRUCTURED UPSTREAM CONTEXT
==================================================

If useful to preserve the root-cause capability, allow a frame event to carry optional context such as:

precededBy:
- poor_position
- poor_speed
- poor_pattern
- tactical_error

or an equivalent clean representation.

Examples:

reported:
missed_pot

precededBy:
poor_position

may support:

direct skill:
Potting

inferred root cause:
Positional Execution

reported:
missed_pot

precededBy:
poor_speed

may support:

direct skill:
Potting

inferred root cause:
Speed Control

Do not require this extra field in normal quick logging.

It is optional evidence only.

==================================================
5. DIAGNOSTIC CONFIDENCE
==================================================

When no upstream evidence exists:

inferredCause = null
diagnosticConfidence = 0 or equivalent "insufficient"

When structured evidence exists:

use an appropriate conservative numeric confidence.

Do not represent speculation as a confident diagnosis.

==================================================
6. PLAYER-REPORTED VS INFERRED REMAINS SEPARATE
==================================================

Preserve:

reportedCause
inferredCause
diagnosticConfidence

The player's reported MISS must not be overwritten even when a valid upstream cause is inferred.

==================================================
7. FIX "EDIT LAST FRAME"
==================================================

The current UI removes the frame before the edit is confirmed.

That is unsafe.

Replace delete-then-reenter behaviour with true edit semantics.

Required behaviour:

1. Player taps "Edit last frame"
2. Existing frame remains stored
3. Edit screen opens with current values preloaded
4. Player changes fields
5. Only when Save/Confirm is pressed does the frame get replaced/updated
6. If player taps Cancel:
   - original frame remains completely unchanged
   - score remains unchanged
   - match evidence remains unchanged

Use the existing editFrame() pure function or equivalent.

Do NOT implement edit by deleting first.

==================================================
8. FRAME EDIT FIELDS
==================================================

At minimum preload and allow editing of the currently supported fields:

- win/loss
- key error / category
- impact
- positive event if supported
- clearance opportunity/outcome if currently present

Do not add new logging fields in this patch.

==================================================
9. EDIT MUST RECOMPUTE DERIVED MATCH EVIDENCE
==================================================

After a confirmed frame edit:

- score updates correctly
- match summary updates correctly
- match-priority evidence recomputes
- next generated training session reflects corrected data

Do not retain stale derived evidence from the old version of the frame.

==================================================
10. CANCEL MUST BE NON-DESTRUCTIVE
==================================================

Explicitly test:

Edit frame
→ change values
→ Cancel

Expected:

- original frame preserved
- original score preserved
- original match evidence preserved

This is required.

==================================================
11. MIXED TRAINING MUST USE MATCH-DERIVED RULESET EVIDENCE
==================================================

Current Mixed Training allocation uses training/profile evidence when deciding:

Blackball vs International

That must now also include ruleset-specific match evidence.

This applies only to rules-sensitive training.

Shared execution remains shared.

==================================================
12. MIXED MODE — MATCH-AWARE RULESET ALLOCATION
==================================================

When preferredRulesMode = "mixed":

derive the Blackball/International allocation from BOTH:

A. ruleset-specific training/profile evidence
B. ruleset-specific real-match evidence

Use the existing minimum floor for both rulesets, e.g. 25%.

Do not allow one ruleset to disappear entirely.

==================================================
13. MIXED MODE PRIORITY ORDER
==================================================

Use this logic:

1. If one ruleset has insufficient confidence:
   prioritize calibration for that ruleset.

2. If both rulesets have adequate confidence:
   consider both:
   - training performance
   - match performance
   - recent high-impact match evidence

3. If one ruleset is clearly weaker in meaningful real-match decision performance:
   allocate more rules-sensitive content to that ruleset.

4. Preserve the minimum exposure floor for both.

==================================================
14. MATCH IMPACT SHOULD MATTER TO MIXED ALLOCATION
==================================================

A decisive/high-impact International tactical breakdown should contribute more to International rules-sensitive allocation than a low-impact International error.

Use the existing match impact and recency weighting.

Do not duplicate match analytics logic unnecessarily.

Prefer reusing:

computeMatchPriorityBoost()
or another existing match-evidence helper

through a small ruleset-specific aggregation helper.

==================================================
15. MATCH RECENCY SHOULD MATTER
==================================================

Recent ruleset-specific match issues should affect Mixed allocation more than old equivalent issues.

Raw match history remains preserved.

Only current training relevance decays.

==================================================
16. DO NOT MUTATE SHARED EXECUTION RATINGS
==================================================

Nothing in this patch should duplicate or reset physical skill ratings.

Potting, Speed, Cue-Ball Control, Positional Execution, etc. remain shared.

Ruleset-specific allocation applies only to rules-sensitive content/evidence.

19. ADD PHASE 3.1 REGRESSION TESTS BO–BZ
==================================================

Add deterministic tests:

BO. Plain miss has no invented root cause
A missed_pot with no upstream evidence records Potting as the direct skill and inferredCause = null.

BP. Position-supported miss
A missed_pot explicitly preceded by poor_position can infer Positional Execution as upstream while preserving the Potting miss.

BQ. Speed-supported miss
A missed_pot explicitly preceded by poor_speed can infer Speed Control as upstream while preserving the Potting miss.

BR. Diagnostic confidence
No-evidence inference has zero/insufficient confidence; structured upstream evidence produces a non-zero conservative confidence.

BS. Edit preserves frame until save
Opening Edit Last Frame does not remove or alter the original frame.

BT. Edit cancel
Cancelling an edit leaves the original frame, score, summary, and derived match influence unchanged.

BU. Edit save
Saving an edited frame changes the frame and recomputes score/evidence correctly.

BV. Edit changes future training
If the edited frame removes a decisive Speed error, the next adaptive session no longer receives the same stale Speed match-priority boost.

BW. Mixed match-aware allocation
With adequate Blackball and International confidence, repeated decisive International tactical errors increase International rules-sensitive allocation.

BX. Mixed Blackball equivalent
Repeated decisive Blackball tactical errors increase Blackball rules-sensitive allocation.

BY. Mixed impact sensitivity
A decisive ruleset-specific match error affects Mixed allocation more than an otherwise identical low-impact error.

BZ. Mixed floor preservation
Even when one ruleset is clearly weaker, the stronger ruleset retains the configured minimum exposure floor.
