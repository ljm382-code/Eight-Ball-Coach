The critical principle is:

SHARED ENGINE
+
RULESET-SPECIFIC RULES

Do NOT duplicate the coaching engine.

==================================================
6. GROUP ASSIGNMENT
==================================================

Implement correct group-state handling for both rulesets.

Represent at minimum:

- open table / groups not yet assigned
- player group
- opponent group
- player object balls remaining
- opponent object balls
- 8-ball / black

Do not assume groups are always known at the start of a scenario.

The ruleset module should determine when groups become assigned.

==================================================
7. LEGAL BALL SELECTION
==================================================

Create a pure rules-layer helper such as:

getLegalBalls(tableState, ruleset)

or equivalent.

The UI must not decide legality itself.

The rules layer determines which balls may legally be selected/played.

This must account for:

- group state
- player group
- 8-ball eligibility
- ruleset
- relevant foul/free-shot state where supported

Current clearance drills should only offer legal player targets.

Opponent balls can remain visually present as obstacles/tactical objects.

==================================================
8. 8-BALL / BLACK ELIGIBILITY
==================================================

Create pure logic such as:

isEightBallLegal(tableState, ruleset)

or equivalent.

The 8-ball/black should only become selectable when legally available under the active ruleset.

Do not hard-code this directly in ClearanceRunner.

==================================================
9. BREAK RULES
==================================================

Represent break rules separately per ruleset.

For the current MVP, accurately model at least what is required for:

- legal break determination
- group state after break
- 8-ball/black on break where relevant
- continuation / turn implications relevant to current scenarios

Do not implement obscure referee procedures unless needed by the app.

==================================================
10. FOUL CONSEQUENCES
==================================================

Blackball and International Rules must not share one generic foul treatment.

Model ruleset-specific consequences.

At minimum capture the differences necessary for tactical scenario evaluation, including:

- incoming player entitlement
- cue-ball placement
- free-shot/free-play implications where applicable
- continuation state

Keep the API modular so more detailed foul logic can be added later.

27. ADD PHASE 2 TESTS P–X
==================================================

Add deterministic tests for:

P. Ruleset persistence
Selecting International Rules persists through profile serialization/storage.

Q. Shared execution profile
Switching Blackball → International does not reset Potting, Speed, Cue-Ball Control or other shared execution ratings.

R. Ruleset filtering
A Blackball-only decision scenario is never selected while International Rules is active, and vice versa.

S. Legal-ball filtering
A player is never offered an opponent-group ball as an ordinary legal clearance target unless the active rules/state explicitly permits it.

T. 8-ball legality
The 8-ball/black is unavailable until legally on under the active ruleset.

U. Ruleset-dependent scenario
One authored table state can produce different decision evaluation under Blackball and International Rules where a genuine rule difference requires it.

V. Ruleset-specific confidence
A player with strong Blackball tactical evidence but no International tactical evidence still has low/insufficient International-specific tactical confidence.

W. Ruleset switch preserves history
Changing preferred rules does not erase attempts, sessions, rating history or progress data.

X. Decision/execution independence under rules
A legal/optimal decision followed by execution failure credits decision evidence and penalizes execution separately; a poor decision followed by successful execution does the reverse.
