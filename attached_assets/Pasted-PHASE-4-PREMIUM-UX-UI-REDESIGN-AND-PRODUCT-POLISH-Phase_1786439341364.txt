PHASE 4 — PREMIUM UX/UI REDESIGN AND PRODUCT POLISH

Phases 1, 2, 2.1, 3 and 3.1 are complete.

The functional intelligence core is now FROZEN.

Current baseline includes:

- 8-Ball Coach product identity
- Blackball Rules
- International Rules
- Mixed Training mode
- adaptive training engine
- shared execution profile
- ruleset-specific decision evidence/confidence
- real-match intelligence
- match/frame logging
- frame-impact weighting
- match-aware limiting factors
- safe frame editing
- ruleset-aware Mixed allocation
- local persistence
- 149 deterministic tests passing
- clean TypeScript
- clean production build
- GitHub source control

DO NOT redesign, rewrite, simplify, or retune the coaching engine.

The only objective of Phase 4 is:

MAKE THE EXISTING APP FEEL LIKE A PREMIUM, MODERN, MOBILE-FIRST 8-BALL COACHING PRODUCT.

This is a UX/UI and interaction-polish phase.

Do NOT add:
- authentication
- backend/database
- cloud persistence
- payments
- video analysis
- AI computer vision
- opponent scouting
- tournament management
- new adaptive algorithms
- new match-analysis logic

==================================================
1. PRIMARY DESIGN GOAL
==================================================

8-Ball Coach should feel:

- premium
- serious
- modern
- focused
- calm
- sports-performance oriented
- unmistakably related to cue sports

It should NOT feel like:

- a generic SaaS dashboard
- a school/trivia app
- a bright corporate app
- a cartoon game
- a casino/gambling app
- a cluttered analytics tool

The experience should feel closer to:

a modern performance-coaching app
+
a high-end cue-sports visual identity

==================================================
2. PRESERVE FUNCTIONAL BEHAVIOUR
==================================================

This is critical.

Do NOT change:

- skill definitions
- rating calculations
- confidence calculations
- limiting-factor logic
- root-cause logic
- match-priority logic
- Mixed allocation logic
- session-generation behavior
- rules legality
- ruleset logic
- persistence semantics
- test expectations

Only change engine-related code if required for presentational integration and only if behavior remains identical.

All existing 149 tests must remain green.

==================================================
3. BEFORE REDESIGNING
==================================================

First:

1. Inspect the current rendered app on mobile dimensions.
2. Identify every current screen/state.
3. Create a concise UI inventory.
4. Note where UI is currently:
   - visually weak
   - cramped
   - unclear
   - repetitive
   - inconsistent
   - overly text-heavy
5. Preserve all current flows.

Then implement the redesign.

Do not replace functioning flows with different product logic.

==================================================
4. DESIGN LANGUAGE
==================================================

Use a refined cue-sports-inspired palette.

Maintain the existing dark direction but make it more sophisticated.

Suggested palette direction:

Background:
deep charcoal / near-black green

Surface:
subtle layered dark green-charcoal

Primary accent:
muted brass / warm gold

Secondary accent:
cool chalk blue

Positive:
controlled emerald / baize green

Negative:
muted burgundy / rust

Text:
warm off-white rather than pure white

Avoid:
- neon colors
- excessive gradients
- glassmorphism everywhere
- huge shadows
- overly bright outlines

Use gradients only very subtly where they add depth.

==================================================

- small section labels
- ruleset badges
