PHASE 5 — TRAINING CONTENT QUALITY, DYNAMIC DECISIONS & REMAINING DIAGRAM FIXES

Phase 4 rendering infrastructure is now the LOCKED BASELINE.

Do NOT redesign or rewrite the renderer architecture.

The following Phase 4 systems are considered stable and must not be replaced:

* PoolTable
* shared English table geometry helper
* rack-left / baulk-right orientation
* cue-ball canonical colour logic
* player-group header logic
* focusBallId
* target-zone rendering
* aim/potting-line rendering
* route rendering
* target-pocket rendering
* table markings rendering
* training labels
* visual contracts
* geometry validation
* generic-fallback removal
* TrainingDiagramAudit
* session filtering of invalid drills

However:

If a CURRENT PLAYABLE DRILL still renders incorrectly because its authored data is incomplete, miswired, or not reaching the existing renderer, FIX THAT SPECIFIC DRILL/DATA PATH.

Do not use “renderer is locked” as a reason to leave a broken live drill.

The goal of Phase 5 is:

1. fix the remaining incorrect drill diagrams;
2. make drills more spatially varied and realistic;
3. remove predictable decision-answer patterns;
4. remove duplicate/weak answer options;
5. make wording and diagrams agree exactly;
6. improve coaching realism without changing adaptive mathematics.

3. FIX LONG POT — FULL LENGTH

The current live Long Pot — Full Length is wrong.

It currently uses the short table dimension.

This drill must run predominantly along the LONG axis.

Required result:

* cue ball near the right/baulk-side half
* object ball toward the left/rack-side end
* target pocket at the left end
* shot travels most of the playable table length
* white cue → object line visible
* object → target pocket line visible

The distance along the long axis must be substantially greater than cross-table displacement.

Add:

shotAxis: "long"

and validate it against the authored coordinates.

⸻

4. LONG-POT DISTANCE REQUIREMENT

Add a helper or validation rule:

isLongAxisShot(diagram)

For Long Pot:

* abs(deltaX) must be clearly greater than abs(deltaY)
* long-axis separation should cover at least approximately 55% of playable table length

Do not accept a short-axis shot simply because total Euclidean distance is large.

⸻

5. FIX SCREW SHOT

The current Screw Shot also uses the short axis.

Redesign its authored geometry to use the LONG axis.

Required:

* white cue ball to the right
* yellow/red object ball nearer mid/left
* target pocket to the left
* potting line along the long axis
* separate backward cue-ball draw route
* visible screw-back target zone behind the cue ball/contact direction

Do not make Screw Shot look like Stop Ball with a box added.

6. SCREW SHOT VISUAL SEMANTICS

The player must be able to identify three distinct things:

1. cue → object
2. object → pocket
3. cue ball draw-back route after impact

Do not invent a new visual system.

7. EXECUTION DRILL SPATIAL VARIETY

Audit all execution drills and classify each:

type ShotAxis = "long" | "cross" | "diagonal" | "mixed";

Add shotAxis metadata where useful.

Target broad variety across the library:

* approximately 50–60% long-axis
* 15–20% cross-table
* 20–25% diagonal
* remainder mixed/multi-cushion

These are QA targets, not adaptive weights.

Do not mechanically force percentages if a skill requires another geometry.

⸻

8. MOST PHYSICAL DRILLS SHOULD USE THE LONG TABLE DIMENSION

When there is no coaching reason to use the short dimension, prefer long-axis geometry.

Especially for:

* long pots
* screw/draw drills
* long follow drills
* speed control
* break-position recovery
* pressure pots
* positional transitions

Cross-table setups should remain where they genuinely teach something.
