2. CRITICAL — FAILED BALLS MUST NOT BE TREATED AS POTTED
==================================================

The current clearance runner must distinguish clearly between:

- balls attempted
- balls successfully potted
- balls still available

A failed shot must NOT:

- be added to pottedRoute
- be removed from remaining balls
- be treated as cleared

unless the active drill failure mode explicitly ends or resets the clearance.

Required concepts:

plannedRoute
attemptedRoute
pottedRoute

Example:

Planned:
Y1 → Y2 → Y3 → EIGHT

Attempts:
Y1 → Y2 → Y2 → Y3 → EIGHT

Potted:
Y1 → Y2 → Y3 → EIGHT

A miss on Y2 belongs only in attemptedRoute until Y2 is actually potted.

Replace ambiguous route recording with explicit fields:

4. PLAN QUALITY MUST NOT BE AUTO-OPTIMAL
==================================================

The current plan-confirm flow must NOT automatically award:

tier: "optimal"
value: 1

simply because the player confirmed a route.

Evaluate the player's planned route against authored route metadata.

At minimum support:

preferredRoute
acceptableRoutes

and derive:

optimal
acceptable
highrisk
poor

Use a pure helper such as:

evaluatePlannedRoute(route, clearance)

or equivalent.

Execution outcome must not influence initial plan quality.

==================================================
5. ADAPTATION CHOICES MUST UPDATE THE CORRECT DECISION SKILL
==================================================

Do not route every adaptation choice to Pattern Recognition.

Use context-aware mapping.

Examples:

Re-plan clearance
→ Pattern Recognition & Clearance Planning

Continue original route
→ Pattern Recognition & Clearance Planning

Develop a problem ball
→ Problem-Ball Identification & Management

Play safe
→ Tactical / Safety Decision-Making

Other
→ contextual/fallback decision skill

Store:

- decision skill
- choice
- tier
- value
- active ruleset where rules-sensitive

Do not penalize or reward execution skills from the adaptation decision itself.

==================================================
6. RULES-SENSITIVE CLEARANCES MUST HAVE AN EXPLICIT RULESET
==================================================

Every clearance whose legality or tactical interpretation depends on rules must run under exactly one real ruleset:

blackball
or
international

Mixed Training is NOT a ruleset.

In mixed mode, the session generator must assign a concrete ruleset to each rules-sensitive clearance.

Store that ruleset on:

- clearance activity
- plan decisions
- ball-selection decisions
- adaptation decisions
- rules-sensitive clearance attempts

Do NOT store rules-sensitive clearance evidence as ruleset: null.

Rule-neutral execution evidence may remain shared/null where genuinely appropriate.

==================================================
7. CLEARANCE DECISION EVIDENCE MUST REMAIN SEPARATE FROM EXECUTION
==================================================

For clearance decisions:

Poor choice + successful pot:
Decision decreases
Execution improves

Optimal choice + miss:
Decision improves
Execution decreases

Do not allow clearance outcome to silently overwrite decision quality.

Preserve the Decision / Execution / Outcome separation.

==================================================
8. LIMITING FACTOR MUST INFLUENCE SESSION WEIGHTING
==================================================

The current execution/decision split must not rely only on composite difference.

Implement:

1. Base weighting from Execution vs Decision composites.
2. Apply an adjustment based on the current limiting factor.
3. Clamp to 25–75%.

Suggested configurable behaviour:

Confirmed execution limiting factor:
meaningful move toward Execution

Confirmed decision limiting factor:
meaningful move toward Decision

Provisional limiting factor:
smaller adjustment

Insufficient evidence:
no limiting-factor override

Do not hard-code values outside the existing config system.

==================================================
9. MAINTENANCE MUST BE ACTUALLY DUE
==================================================

Do not select maintenance merely because a skill is strong.

Maintenance eligibility must consider at least:

- skill strength
- confidence
- time since last trained
- recent representation in sessions

A strong skill trained recently should not consume a maintenance slot.

If no skill is genuinely due, do not force maintenance.

Create a pure selector such as:

selectMaintenanceSkill(profile)

or equivalent.

==================================================
10. SESSION SIZE MUST RESPECT THE REQUESTED TARGET
==================================================

Do not generate the normal target count and then append a clearance.

If the session target is:

15 min → 3 activities
30 min → 5 activities
45 min → 7 activities
60 min → 9 activities
90 min → 13 activities

and one clearance is included, reserve one of those slots.

Example:

30-minute target = 5

4 normal activities
+ 1 clearance
= 5 total

Do not silently create 6.

==================================================

4. Keep shared execution drills rule-neutral where appropriate.

Do not duplicate shared physical ratings.

19. ADD PHASE 2.1 REGRESSION TESTS
==================================================

Add these deterministic tests:

AE. Missed ball stays available
A failed clearance shot is added to attemptedRoute but not pottedRoute and remains available unless the failure mode ends/resets the clearance.

AF. Successful retry
After a miss, retrying and potting the same ball records two attempts but one potted entry.

AG. Plan quality
A poor planned route does not receive Optimal decision credit.

AH. Acceptable route
An authored acceptable alternative receives Acceptable rather than Optimal or Poor.

AI. Adaptation skill mapping
"Play safe" updates Tactical Decision-Making, "Develop a problem ball" updates Problem-Ball Decision, and "Re-plan clearance" updates Pattern Recognition.

AJ. Clearance ruleset tagging
A rules-sensitive clearance in Mixed mode has exactly one active real ruleset and stores it on rules-sensitive decision evidence.

AK. Confirmed limiting-factor weighting
A confirmed decision limiting factor shifts the session materially toward Decision even when composites are close.

AL. Maintenance due
A strong skill practiced recently is not selected for maintenance over an equally strong stale skill.

AM. No forced maintenance
If no strong skill is due, session generation does not invent maintenance.

AN. Session size
Generated activity count matches the target for 15/30/45/60/90-minute sessions after clearance insertion.

AO. Final composition
A meaningful-length session still contains both execution and decision activities after maintenance/calibration/supporting substitutions.

AP. Root-cause decay
Recent root-cause evidence contributes more than old root-cause evidence.

AQ. Root-cause confidence
High-confidence root-cause evidence contributes more than low-confidence evidence of the same age.

AR. Root-cause shift
Old evidence from a previously fixed weakness no longer dominates once newer evidence points elsewhere.

AS. Mixed performance allocation
With adequate confidence in both rulesets, weaker International decision performance produces more International rules-sensitive work than Blackball while preserving the minimum Blackball floor.

AT. Mixed calibration precedence
If International confidence is low but Blackball confidence is high, International receives extra calibration even before a stable performance comparison exists.

AU. Shared execution neutrality
Shared execution attempts still do not inflate Blackball- or International-specific tactical confidence.

AV. Rules source consistency
Implemented Blackball and International helper behaviour used by current scenarios matches the authoritative rule definitions encoded in the modules.
